# Canary audio assets

The `.wav` files referenced by `manifest.json` are **generated by a separate part of the
project** (the TTS/audio team), not by this app. Drop the pre-generated files here, or point
`audioUrl` at wherever they are served (a backend endpoint later).

> `lighthouse.wav` / `orchard.wav` currently in this folder are **throwaway local test
> stand-ins** made with the macOS `say` command (`say -o x.aiff "…"; afconvert -f WAVE -d
> LEI16@22050 x.aiff x.wav`). Replace them with the real assets. Regenerate with any voice; then
> update `durationMs` in `manifest.json` to the file's real length (`afinfo x.wav`).

This app only **loads, schedules, previews, mixes, transmits, logs, and analyzes** them. It
never synthesises audio.

Each entry matches the `AudioCanary` shape in `web/lib/canary.ts`. `expectedMarker` is the
concept the canary tries to elicit; marker detection after transcription looks for it.

Every use of a canary in a live interview is gated on the candidate having consented to
"measures to detect the use of unauthorized real-time assistance tools" (see SPEC §6). The app
enforces that gate; do not bypass it.
